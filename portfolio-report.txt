PORTFOLIO MANAGEMENT REPORT — MILESTONE M2
===========================================

1. PORTFOLIO ARCHITECTURE
=========================

The Portfolio feature is a standalone module (src/features/portfolio/) following
the project's layered architecture:

  portfolio/
  ├── application/        # Use cases, interfaces, mappers
  │   ├── interfaces/     # Repository + use-case contracts
  │   ├── mappers/        # Entity → DTO mapping
  │   └── use-cases/      # Create/List/Get portfolio, Create/Update/Delete/List holding
  ├── domain/             # Entities, enums, errors
  │   ├── entities/       # Portfolio + Holding TypeORM entities
  │   ├── enums/          # PortfolioSourceType, PortfolioErrorCode
  │   └── errors/         # Domain error factories
  ├── infrastructure/     # TypeORM repositories, DB race guard
  │   ├── providers/      # unique-constraint.handler
  │   └── repositories/   # PortfolioRepository, HoldingRepository
  ├── presentation/       # Controllers, DTOs, Swagger
  │   ├── controllers/    # PortfoliosController, HoldingsController
  │   ├── dto/            # Request/response DTOs
  │   ├── validators/     # IsDecimalString custom validator
  │   └── swagger/        # API documentation decorators
  └── portfolio.module.ts # NestJS module wiring

Design principle: a portfolio is a user-owned aggregation point ("source"):
a wallet or exchange. Holdings attach assets to a portfolio. Every resource is
scoped to the authenticated user; a resource owned by someone else is reported
as 404 (never 403) so ownership cannot be probed by identifier.

A new cross-cutting `Trim` transform decorator was added under
src/presentation/validation/ so names/notes are trimmed before validation.

3. MONEY STRATEGY
=================

`amount` is stored as TypeORM `decimal(36,18)` (PostgreSQL `numeric`) and typed
as `string` in the entity, DTOs and mapper. It is never coerced through a
JavaScript float:

- Clients send the amount as a decimal string.
- A custom validator (IsDecimalString) accepts only `^\d+(\.\d{1,18})?$` and
  rejects zero patterns, so `amount` is a positive number with at most 18
  fractional digits.
- PostgreSQL enforces a CHECK constraint ("amount" > 0) as a second line of
  defence.
- The stored value is echoed back unchanged (full precision preserved).

This mirrors the existing assets convention (decimal-as-string).


4. CONCURRENCY SAFETY
=====================

One holding per (portfolio, asset) is enforced twice:

1. The create-holding use case checks for an existing holding before inserting
   (a friendly 422 HOLDING_ALREADY_EXISTS path, without a unique-violation).
2. The UNIQUE index IDX_holding_portfolio_asset closes the race between the
   check and the insert. unique-constraint.handler.ts re-maps the PostgreSQL
   23505 violation back to the same 422 so clients see one consistent error.

A holding can therefore never be duplicated, even under concurrent writes.


5. API ENDPOINTS
================

POST /v1/portfolios
  Auth:   Authenticated + CSRF
  Body:   { name, sourceType, walletAddress? }
  Returns: PortfolioResponseDto (201)
  422:    Validation failure

GET /v1/portfolios
  Auth:   Authenticated
  Returns: PortfolioResponseDto[] (200) — reverse creation order

GET /v1/portfolios/:id
  Auth:   Authenticated
  Returns: PortfolioResponseDto (200)
  404:    Unknown/foreign portfolio
  422:    Invalid UUID

POST /v1/holdings
  Auth:   Authenticated + CSRF
  Body:   { portfolioId, assetId, amount, notes? }
  Returns: HoldingResponseDto with embedded asset (201)
  404:    Unknown/foreign portfolio, or unknown asset
  422:    Validation failure, or HOLDING_ALREADY_EXISTS

GET /v1/holdings?portfolioId=
  Auth:   Authenticated
  Returns: { items: HoldingResponseDto[], nextCursor: null } (200)
  Notes:  Response is shaped like a cursor page so a cursor can be added
          without breaking clients; today the full list is returned and
          nextCursor is always null.

PATCH /v1/holdings/:id
  Auth:   Authenticated + CSRF
  Body:   { amount?, notes? } — at least one field
  Returns: HoldingResponseDto (200)
  404:    Unknown/foreign holding
  422:    Validation failure, or HOLDING_EMPTY_UPDATE (empty body)

DELETE /v1/holdings/:id
  Auth:   Authenticated + CSRF
  Returns: 204 No Content
  404:    Unknown/foreign holding
  422:    Invalid UUID

Error codes (ErrorDomain.PORTFOLIO):
  PORTFOLIO_NOT_FOUND       (404)
  PORTFOLIO_ASSET_NOT_FOUND (404)
  HOLDING_NOT_FOUND         (404)
  HOLDING_ALREADY_EXISTS    (422)
  HOLDING_EMPTY_UPDATE      (422)


6. AUTHORIZATION MODEL
=====================

All portfolio/holding endpoints require authentication (JwtGuard is APP_GUARD).
Mutations additionally require a valid x-csrf-token header (CsrfGuard, APP_GUARD).

Ownership is enforced in the repositories/use cases via the authenticated
userId on every query:
  - findByIdAndUser / findByIdAndUser → a foreign id resolves to 404.
  - listByUser / findByUserId filter by the caller's userId.

No PORTFOLIO_* permissions were introduced: ownership is intrinsic to the
resource, and read is authn-only for regular users, matching the assets model.

10. REMAINING CONSIDERATIONS
============================

a) Cursor pagination: GET /v1/holdings returns the full list with nextCursor
   fixed to null. The response shape is already a cursor page, so adding real
   cursor pagination (mirroring GET /v1/assets) is a non-breaking follow-up.

b) Portfolio update/delete: A portfolio source can currently be created, listed
   and fetched but not renamed or removed. Deleting a portfolio is intentionally
   deferred until the holdings lifecycle is settled (FK is ON DELETE NO ACTION).

c) Valuation: Holdings store raw amounts only. Price context lives on the asset
   (currentPrice). A portfolio valuation endpoint (amount × price) is a natural
   follow-up once cursor pagination lands.

d) Trim coverage: Only name/notes/walletAddress are trimmed. Amounts are not
   trimmed because whitespace inside a decimal string is rejected by the
   IsDecimalString validator anyway.

e) Concurrency at scale: create-holding relies on a check-then-insert with a
   UNIQUE index fallback. Under very high write throughput the 23505 → 422
   remap keeps the contract stable; no advisory locking was needed.

f) The portfolio module currently depends on AssetsModule's repository export
   (ASSET_REPOSITORY) to validate assetId. If other modules need asset reads
   later, the assets application layer could expose a dedicated read port.
