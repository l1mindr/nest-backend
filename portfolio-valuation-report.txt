PORTFOLIO VALUATION REPORT — MILESTONE M4
==========================================

1. OBJECTIVE
============

Compute the current value of a portfolio source from the holdings recorded in
M2/M3: each holding value is `amount × currentPrice`, and the portfolio total
is the exact sum of every valued holding.

Values are computed on demand and never persisted. No CoinGecko call is made on
this path — the price consumed is the last one the asset synchroniser stored in
`asset.currentPrice`. No P&L, transactions, snapshots, or foreign-currency
conversion were added; the API is intentionally read-only.

The central constraint: no JavaScript float arithmetic anywhere. `0.1 × 0.2`
must be exactly `0.02`, never `0.020000000000000004`.


2. DECIMAL CALCULATION BOUNDARY
===============================

No decimal/money library exists in the project, so one was introduced as the
smallest appropriate boundary: a BigInt-based exact decimal utility.

  src/core/decimal/decimal.util.ts
  src/core/decimal/__tests__/decimal.util.spec.ts

Design:
- A decimal string is parsed into an integer coefficient plus a scale
  (`'123.450'` -> `{ coefficient: 123450n, scale: 3 }`) — never through a float.
- multiplyDecimals(a, b): exact product; the resulting scale is the sum of the
  two input scales. `amount` (numeric(36,18)) × `price` (numeric(30,8)) keeps
  up to 26 fractional digits, so no rounding occurs before the value is used.
- sumDecimals(values): every value is normalised to the highest scale present
  before adding, so `'0.1' + '0.2'` is exactly `'0.3'`.
- Output strings are trimmed of trailing fractional zeros: `'90000'`, never
  `'90000.000000000000000000'`.

This deliberately adds no new dependency and mirrors the existing core/ util
pattern (e.g. core/pagination). Framework-agnostic; unit-tested in isolation
including the 0.1 × 0.2 precision case.


3. DOMAIN MODEL
===============

  src/features/portfolio/domain/enums/portfolio-valuation-status.enum.ts
  src/features/portfolio/domain/portfolio-valuation.constants.ts

PortfolioValuationStatus:
  COMPLETE     — every holding has a usable price
  PARTIAL      — some but not all holdings have a usable price
  UNAVAILABLE  — holdings exist but none has a usable price
  EMPTY        — the portfolio holds nothing

PORTFOLIO_VALUATION_CURRENCY = 'USD':
  CoinGecko prices are synchronised with `vs_currency: usd`
  (src/features/assets/infrastructure/coingecko/coingecko.provider.ts), so USD
  is the single quote currency. Exposed on every valuation response.


4. USE CASE
===========

  src/features/portfolio/application/use-cases/get-portfolio-valuation.use-case.ts
  src/features/portfolio/application/use-cases/__tests__/get-portfolio-valuation.use-case.spec.ts

GetPortfolioValuationUseCase.execute(userId, portfolioId):
  1. portfolioRepository.findByIdAndUser(portfolioId, userId)
     → PORTFOLIO_NOT_FOUND (404) when absent or owned by another account.
  2. holdingRepository.listForValuation(portfolioId) — one query, joins the
     asset so its price is loaded with the holding (no N+1).
  3. Per holding: value = multiplyDecimals(amount, currentPrice), or null when
     the asset has no price.
  4. Total = sumDecimals over valued holdings; null when none could be valued.
  5. Status resolved from the valued/unvalued counts.
  6. Logs LogEvent.PORTFOLIO_VALUATION_COMPUTED.

Repository addition (src/features/portfolio/infrastructure/repositories/holding.repository.ts):
  listForValuation(portfolioId) — LEFT JOIN asset, ordered by createdAt ASC.
  Interface contract added to IHoldingRepository in
  src/features/portfolio/application/interfaces/portfolio.interface.ts.

Domain result types:
  PortfolioHoldingValuation { holdingId, assetId, symbol, name, amount,
                              currentPrice, value }
  PortfolioValuation       { portfolioId, currency, totalValue, status,
                             valuedHoldings, unvaluedHoldings, holdings }


5. API ENDPOINT
===============

  GET /v1/portfolios/:id/valuation   (read-only, authenticated only)

Response (200):
  {
    "portfolioId":   "...",
    "currency":      "USD",
    "totalValue":    "96000",          // string | null (null when nothing valued)
    "status":        "COMPLETE",       // COMPLETE | PARTIAL | UNAVAILABLE | EMPTY
    "valuedHoldings": 2,
    "unvaluedHoldings": 0,
    "holdings": [
      { "holdingId": "...", "assetId": "...", "symbol": "btc",
        "name": "Bitcoin", "amount": "1.500000000000000000",
        "currentPrice": "60000.00000000", "value": "90000" }
    ]
  }

Semantics:
  - Every price/value is a decimal string; nothing is coerced through a float.
  - A holding without a price reports `currentPrice: null` and `value: null`
    and is excluded from the total (never treated as zero).
  - Empty portfolio: EMPTY, totalValue null, holdings [].
  - All priced: COMPLETE. Some priced: PARTIAL. None priced: UNAVAILABLE.

Presentation:
  - DTOs:      src/features/portfolio/presentation/dto/response/portfolio-valuation.response.dto.ts
  - Mapper:    src/features/portfolio/application/mappers/portfolio-valuation.mapper.ts
  - Handler:   GET /portfolios/:id/valuation on PortfoliosController
  - Swagger:   ApiGetPortfolioValuation in portfolio.swagger.ts
               (operationId getPortfolioValuation, error catalog + 404 ownership)

The `/portfolios/:id` route is declared before `/portfolios/:id/valuation`;
Express matches `:id` against a single segment, so no conflict exists.


6. AUTHORIZATION MODEL
======================

Identical to the rest of the feature:
  - JwtGuard (APP_GUARD) requires authentication on every endpoint.
  - Ownership is checked via findByIdAndUser before any holding query runs.
  - A portfolio owned by another account is reported as 404 PORTFOLIO_NOT_FOUND,
    indistinguishable from a non-existent one (no ownership probing).
  - No role/permission checks; valuation is scoped purely by the authenticated
    userId derived from @User().

No CSRF guard needed: this is a GET (read-only), like the existing reads.

10. REMAINING CONSIDERATIONS
============================

a) No stale-price policy: valuation uses the last price stored by the
   synchroniser regardless of age. The asset entity carries only lastSyncedAt
   (no priceUpdatedAt). If the product needs "price older than X is unreliable",
   a freshness policy can be layered into the use case without schema changes.

b) Currency is fixed to USD. If multi-currency quotes are ever needed, the
   currency becomes part of the query and the FX conversion is a new concern;
   today the project's sole quote currency is USD (CoinGecko vs_currency=usd).

c) No value persistence: totalValue is recomputed on every request. For large
   portfolios a cache or a nightly aggregation could be added, but this is not
   needed at current scale and caching would introduce staleness questions.

d) No pagination on the holdings array: a portfolio's holding count is bounded
   and the existing list-holdings page pattern (items/nextCursor) could be
   reused if a portfolio ever grows large.

e) The decimal utility currently supports non-negative values only. Prices and
   amounts are validated positive at write time, so negative inputs cannot
   reach it from this feature; a future use of the utility for P&L (which is
   inherently signed) should extend it rather than work around it.
